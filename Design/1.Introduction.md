
## 3.1 Introduction
### 1) Summary
우리는 일상생활에서 다양한 쓰레기와 재활용품을 배출한다. 하지만 종종 쓰레기를 버리려고 할 때 해당 물품을 어떻게 분리배출해야 하는지 정확히 알지 못해 곤란을 겪는 경우가 있다. 일반적으로 분리배출 방법은 재질, 오염 여부, 지역별 기준에 따라 달라지기 때문에 사용자가 모든 기준을 직접 알고 있기는 어렵다. 특히 플라스틱, 종이, 캔, 유리병처럼 비교적 구분이 쉬운 품목도 있지만, 세부적인 기준이 필요한 품목은 사용자가 직접 검색하거나 안내문을 찾아봐야 하는 불편함이 있다.

하지만 올바른 분리배출 정보는 환경 보호와 재활용률 향상을 위해 사용자에게 꼭 필요한 정보이다. 잘못된 방식으로 쓰레기를 배출하면 재활용이 가능한 물품도 일반 쓰레기로 처리될 수 있으며, 반대로 재활용이 어려운 물품이 재활용품으로 배출되어 선별 과정에 문제를 일으킬 수 있다. 따라서 사용자가 쓰레기를 배출하기 전에 해당 물품의 종류와 처리 방법을 쉽게 확인할 수 있다면 잘못된 분리배출을 줄일 수 있을 것이다.

위의 불편함을 해결하기 위해 사용자가 쓰레기 이미지를 업로드하면 시스템이 해당 이미지를 분석하고, 예측된 쓰레기 종류와 분리배출 방법을 제공하는 시스템인 **Waste Sorting System**을 고안하였다. 이를 통해 사용자는 직접 여러 사이트를 검색하지 않아도 하나의 웹 시스템 안에서 이미지 분석 결과, 상세 가이드, 재활용 정보 검색, 지역별 분리배출 규칙을 확인할 수 있을 것이다.

본 시스템은 외부 AI 판별 API를 호출하는 방식이 아니라, **직접 학습한 YOLO 기반 모델을 백엔드 서버에 탑재**하여 이미지 분류를 수행하도록 설계한다. 사용자가 업로드한 이미지는 FastAPI 서버의 `/predict` 엔드포인트로 전달되며, 서버는 자체 모델 파일을 이용해 쓰레기 종류와 신뢰도를 계산한 뒤 프론트엔드에 결과를 반환하도록 구성할 것이다. 이러한 구조를 통해 본 프로젝트는 단순히 외부 API를 활용하는 것이 아니라, AI 모델 적용 및 서비스 연동 과정을 직접 구현하는 시스템이라는 특징을 가진다.

이 문서는 Waste Sorting System을 개발하기 위한 세 번째 단계인 **Design**에 대한 내용으로, 실제 구현에 대한 세부적인 사항을 명시하고, Diagram들을 통해 시스템의 전반적인 모습을 시각화, 순서화하여 보여준다.

### 2) Important Points of Design
* **권한에 따른 기능 분리**: 사용자의 로그인 여부에 따라 사용 가능한 operation을 구별해야 한다.
* **계층 및 역할 분리**: 프론트엔드와 백엔드의 역할을 분리하여 사용자 화면 처리와 AI 분석 로직이 섞이지 않도록 해야 한다.
* **자체 AI 모델 서빙**: 사용자가 업로드한 이미지는 백엔드 서버로 전달되고, 서버에서 직접 학습한 YOLO 모델을 이용해 분류되도록 해야 한다.
* **낮은 신뢰도 예외 처리**: AI 예측 결과의 신뢰도가 낮은 경우 잘못된 정보를 제공하지 않도록 예외 처리를 해야 한다.
* **데이터 격리 및 보안**: 사용자별 분석 결과를 저장하되, 다른 사용자에게 정보가 노출되지 않도록 해야 한다.
* **캡슐화**: Class 간의 정보 공유는 가능하도록 하되, 중요한 데이터가 외부로 직접 노출되지 않도록 해야 한다.
* **민감 정보 은닉**: API 인증키, 모델 경로, 사용자 비밀번호 등과 같은 민감한 정보는 프론트엔드에 노출되지 않도록 관리해야 한다.
* **모듈 독립성 및 연계성**: 이미지 분석, 재활용 정보 검색, 상세 가이드, 지역별 규칙 조회 기능이 서로 독립적으로 동작하면서도 필요한 정보를 연결할 수 있도록 설계해야 한다.
