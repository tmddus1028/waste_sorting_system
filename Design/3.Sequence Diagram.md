# 3.3 Sequence Diagram
### (1) User Registration and Login
<img width="1178" height="1406" alt="image" src="https://github.com/user-attachments/assets/dc8eb539-d959-4134-b007-99cd5d4c31dd" />
위 그림은 사용자의 회원가입과 로그인 과정을 나타낸다. 사용자가 이름, 이메일, 비밀번호를 입력하면 AuthController가 SupabaseClient를 통해 회원가입 또는 로그인을 요청한다. 회원가입이 성공하면 사용자 정보가 UserProfile에 저장되고, 이후 자동 로그인 상태를 방지하기 위해 로그아웃 처리 후 로그인 페이지로 이동한다. 로그인 과정에서는 SupabaseClient가 이메일과 비밀번호를 확인하고, 인증이 성공하면 UserProfile에서 사용자 이름과 권한 정보를 불러온다. 이후 AuthStorage에 현재 사용자 정보를 저장하여 로그인 상태를 유지한다. 사용자의 권한이 관리자이면 관리자 페이지로 이동하고, 일반 사용자이면 메인 페이지로 이동한다. 실패한 경우에는 오류 메시지를 사용자에게 출력한다.

### (2) Waste Image Upload and AI Prediction
<img width="1824" height="1376" alt="image" src="https://github.com/user-attachments/assets/9c17baba-bcae-4feb-8206-81f6ec80fb69" />
위 그림은 이미지 업로드와 AI 예측 과정을 나타낸다. 사용자는 업로드 화면에서 쓰레기 이미지를 선택하거나 촬영한 뒤 업로드 버튼을 누른다. UploadController는 선택된 이미지를 FastAPI 서버로 전송하고, 서버는 직접 학습한 YOLO 모델을 사용하여 이미지 속 쓰레기 종류를 예측한다. 예측 결과에는 쓰레기 종류, 신뢰도, 분리배출 안내 정보가 포함된다. 서버가 결과를 반환하면 UploadController는 해당 결과를 저장하고 결과 페이지로 이동한다. 사용자는 결과 페이지에서 AI가 예측한 쓰레기 종류와 분리배출 방법을 확인할 수 있다.

### (3) View Prediction Result
<img width="1676" height="1416" alt="image" src="https://github.com/user-attachments/assets/3fd0861c-8734-4944-b486-38acfab3251a" />
위 그림은 AI 분석 결과를 화면에 표시하는 과정을 나타낸다. 사용자가 결과 페이지에 접근하면 ResultController는 로그인 상태를 확인하고, LocalStorage에 저장된 최근 업로드 기록을 불러온다. 최근 기록이 없으면 업로드 페이지로 이동하고, 기록이 있으면 AI 예측 결과에서 model_class 값을 추출한다. 이후 Supabase의 recycling_items 테이블에서 해당 클래스와 연결되는 품목 정보를 조회한다. 조회된 품목 정보가 있으면 품목명, 분류, 재활용 가능 여부, 분리배출 안내를 예측 결과와 함께 화면에 표시한다. 품목 정보가 없을 경우에는 AI 예측 결과를 기본값으로 사용한다. 사용자는 결과 화면에서 분석 이미지와 예측 결과를 확인하고, 필요하면 상세 가이드 페이지로 이동할 수 있다.

### (4) View Detailed Recycling Guide
<img width="2062" height="1368" alt="image" src="https://github.com/user-attachments/assets/e25596ec-9e78-4836-87a8-9789d0edca3b" />
위 그림은 품목별 상세 분리배출 가이드 조회 과정을 나타낸다. 사용자가 가이드 페이지에 접근하면 GuideController는 Supabase의 recycling_guides 테이블에서 가이드 목록을 불러온다. 데이터가 있으면 해당 목록을 화면에 표시하고, 데이터가 없으면 기본 가이드 목록을 표시한다. 사용자가 특정 품목을 선택하면 선택된 type 값을 기준으로 상세 가이드 페이지로 이동한다. GuideDetailController는 URL에서 type 값을 읽고, 해당 품목의 상세 정보를 조회한다. 조회된 데이터가 있으면 세척 방법, 분리 방법, 배출 방법, 주의사항을 화면에 표시하고, 데이터가 없으면 기본 상세 가이드를 사용한다.

### (5) Search Recycling Information
<img width="1906" height="1434" alt="image" src="https://github.com/user-attachments/assets/591784e5-8c90-4152-8069-1c8d63cc6c84" />
위 그림은 사용자가 품목명을 입력하여 재활용 정보를 검색하는 과정을 나타낸다. 사용자가 검색 페이지에서 품목명을 입력하고 검색 버튼을 누르면 SearchController가 입력값을 확인한다. 검색어가 비어 있으면 안내 메시지를 출력하고, 검색어가 있으면 먼저 로컬 재활용 데이터에서 해당 품목을 찾는다.
로컬 데이터에서 검색 결과가 있으면 바로 화면에 재활용 정보를 표시한다. 만약 로컬 데이터에 없는 품목이면 FastAPI 서버의 검색 API로 요청을 보내고, 서버는 공공 재활용 정보 API를 통해 관련 정보를 조회한다. 이후 서버는 API 응답 결과를 정리하여 프론트엔드로 반환한다.
SearchController는 반환된 결과를 검색 화면에 표시하며, 사용자는 품목명, 재활용 가능 여부, 배출 방법 등을 확인할 수 있다. 검색 결과가 없거나 API 오류가 발생한 경우에는 검색 결과가 없다는 안내 메시지를 출력한다.

### (6)	View Local Recycling Rules	
<img width="1590" height="1390" alt="image" src="https://github.com/user-attachments/assets/a180658f-c6f0-408c-be7d-844b63fdc584" />
위 그림은 사용자가 지역별 분리배출 규칙을 조회하는 과정을 나타낸다. 사용자가 지역별 규칙 페이지에 접근하면 LocalRulesController가 시·도 목록을 화면에 표시한다. 사용자가 시·도를 선택하면 해당 지역의 시·군·구 목록이 나타나고, 시·군·구까지 선택하면 최종 지역명이 만들어진다.
지역이 선택되면 LocalRulesController는 해당 지역의 분리배출 정보를 조회한다. 먼저 Supabase의 local_rules 테이블에서 관리자가 추가하거나 수정한 지역별 안내 정보가 있는지 확인한다. 이후 공공데이터 API를 통해 선택한 지역의 생활폐기물 배출 정보를 요청한다.
API 데이터가 있으면 배출 요일, 배출 시간, 배출장소 등의 정보를 화면에 표시한다. 관리자 보정 데이터가 함께 있으면 추가 안내 정보도 같이 보여준다. API 데이터가 없을 경우에는 관리자 보정 데이터나 기본 예시 데이터를 표시하여 사용자가 지역별 분리배출 규칙을 확인할 수 있도록 한다.

### (7)	Manage Recycling Data by Administrator
<img width="1224" height="1438" alt="image" src="https://github.com/user-attachments/assets/648f36e2-9a97-49ad-b83a-8cb5bd230b55" />
위 그림은 관리자가 시스템 데이터를 관리하는 과정을 나타낸다. 관리자가 관리자 페이지에 접근하면 AdminController는 AuthStorage를 통해 현재 사용자가 관리자 권한을 가지고 있는지 확인한다. 관리자 권한이 없는 사용자는 접근이 제한되고, 관리자 권한이 확인된 경우에만 관리자 화면이 표시된다.
관리자는 관리자 화면에서 재활용 품목, 상세 가이드, 지역별 규칙 데이터를 선택하여 조회할 수 있다. 선택한 메뉴에 따라 recycling_items, recycling_guides, local_rules 테이블의 데이터가 Supabase에서 불러와지고, 화면에 목록 형태로 표시된다.
관리자는 필요한 데이터를 추가, 수정, 삭제할 수 있다. 데이터 추가 시에는 입력한 정보가 Supabase 테이블에 저장되고, 수정 시에는 기존 데이터가 변경된다. 삭제 시에는 선택한 데이터가 테이블에서 제거된다. 작업이 완료되면 변경된 데이터를 다시 불러와 관리자 화면에 반영한다. 이를 통해 관리자는 사용자에게 제공되는 재활용 정보와 상세 가이드, 지역별 안내 정보를 직접 관리할 수 있다.
